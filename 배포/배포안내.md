> 대상: 전산 담당 · 작성 2026-11-18 · 요청서: [전산확인요청.md](../시범운영/전산확인요청.md)
> 같은 배포 묶음 하나로 **① 외부 정적 호스팅**과 **② 사내 서버** 어느 쪽에도 올릴 수 있습니다.

## 0. 배포 묶음

| 파일 | 내용 |
|---|---|
| `위생점검웹앱_배포_YYYYMMDD.zip` | 전달용 압축 파일 (약 70KB) |
| `dist\` | 압축을 푼 것과 같은 폴더. **이 폴더 안의 파일을 그대로 올립니다** |
| `dist\배포목록.txt` | 들어 있는 파일 27개의 크기·SHA-256 (변조 확인용) |
| `서버설정\nginx-예시.conf` | nginx 쓸 때만 참고 (웹 폴더에 올리지 않음) |

다시 만들기: `python make_deploy.py` (원본 `현장체크리스트` 폴더를 읽어 dist·zip을 새로 만듦)

**공통 성질**
- 정적 파일만 있음: 서버 프로그램·데이터베이스·로그인 없음
- 외부 라이브러리·외부 사이트 호출 없음. 페이지 안 보안 규칙(CSP)이 자기 주소 외 접속을 막음
- 점검 데이터·연락처·사진은 각 휴대폰 브라우저 안에만 저장, 서버로 전송 안 함
- **https 필수**: 휴대폰 카메라와 오프라인 동작은 https 주소에서만 됨
- 주소의 하위 경로(예: `/hygiene-checklist/`)에 둬도 동작 (모든 경로가 상대 경로)

## ① 외부 정적 호스팅 (GitHub Pages 예)

1. 회사(또는 승인된) GitHub 계정에 새 저장소 생성 — 예: `hygiene-checklist` (공개 저장소에는 **화면 파일만** 올라감, 업무 데이터 없음)
2. `dist\` 안의 파일 전체를 저장소 맨 위에 올림 (`.nojekyll` 포함)
3. 저장소 Settings → Pages → Branch: `main` / `(root)` → Save
4. 1~2분 뒤 주소 확인: `https://<계정>.github.io/hygiene-checklist/`
5. 아래 "4. 올린 뒤 확인" 진행

참고
- GitHub Pages 는 서버 보안 헤더를 바꿀 수 없어서, 보안 규칙(CSP)·referrer 설정을 **페이지 안에 넣어 두었습니다**. `web.config`·`.htaccess` 는 무시되며 그대로 있어도 문제없습니다 (비밀 정보 없음).
- 같은 방식으로 Netlify·Cloudflare Pages 등 다른 정적 호스팅에도 `dist` 를 그대로 올리면 됩니다.

## ② 사내 서버

| 서버 | 할 일 |
|---|---|
| **IIS** | 새 사이트(또는 가상 디렉터리)의 실제 경로를 `dist` 로 지정 → https 바인딩 + 인증서. `web.config` 가 파일 형식·보안 헤더·최신 파일 확인을 설정. http→https 전환은 "URL 재작성" 모듈이 있으면 `web.config` 안 주석을 풀기 |
| **Apache** | DocumentRoot(또는 Alias)를 `dist` 로 → `AllowOverride All` 이면 `.htaccess` 가 적용 (mod_headers·mod_rewrite 필요). 꺼져 있으면 같은 내용을 VirtualHost 에 |
| **nginx** | `서버설정\nginx-예시.conf` 를 참고해 server 블록 작성 (`root` 를 `dist` 로) |

- 개인 휴대폰(외부망)에서 접속할 수 있어야 함: 외부 공개 주소 또는 VPN 등 (전산 결정)
- 서버 쪽 보안 헤더: `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy: camera=(self)`
- `sw.js`·`index.html` 은 `Cache-Control: no-cache` (업데이트 후 옛 화면이 남지 않게)

## 3. 업데이트할 때

1. 화면 파일을 고치면 `현장체크리스트\sw.js` 의 `CACHE` 이름 숫자를 올림 (현재 `v8`)
2. `python make_deploy.py` 로 묶음 다시 만들기
3. `dist` 전체를 같은 위치에 덮어쓰기 → 휴대폰은 다음에 열 때 새 버전으로 바뀜 (입력 데이터는 그대로)
